# Release Notes

## Purpose

Summarize completed changes in terms of user-visible behavior, operational impact, and verification evidence.

## Workflow

1. Read linked tickets and specs.
2. Summarize what changed and why.
3. Include checks run.
4. Mention deferred work and unresolved gates only when relevant.

## Output

Keep notes concise and grouped by behavior or process area.
