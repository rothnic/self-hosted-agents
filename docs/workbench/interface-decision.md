# Interface Decision

Status: defined for Goal 006 T013.

Decision: keep the Goal 006 workbench as CLI/static repo artifacts. Do not build a local UI for this goal unless a later
reviewed decision reopens the interface choice with stronger evidence.

Rejected for now:

- `local-ui`: not selected for Goal 006.

## Comparison

The decision records operating burden, self-hosting requirements, accessibility, small-screen review, automation compatibility,
and source-of-truth preservation.

| Criterion | CLI/static | Local UI |
| --- | --- | --- |
| Operating burden | Low: generated by existing `uv run awf` commands | Medium: adds UI runtime, assets, visual checks, and maintenance |
| Self-hosting requirements | Repo checkout, Python environment, Beads, and `.agent-runs` artifacts | All CLI/static requirements plus a local server or terminal UI runtime |
| Accessibility | Text artifacts work in terminal, editor, PR, or static renderer | Requires explicit accessibility checks before acceptance |
| Small-screen review | Text summaries and PR artifacts remain readable without a custom viewport | Requires responsive layout and small-screen verification |
| Automation compatibility | High: scheduled agents can read JSON and Markdown directly | Medium: agents must avoid depending on a fragile UI process |
| Source-of-truth preservation | Strong: links back to repo artifacts and commands | Risk: UI can hide or summarize away source artifacts |

## Rationale

- The current CLI/static workbench already exposes status, goals, increment state, evidence, review actions, reviewer
  decisions, branch/PR state, trace/eval links, and handoff summaries.
- The workbench is generated from repo state and workflow commands, not prior chat context.
- Deterministic validation remains credential-free and does not require hosted Logfire, hosted Langfuse, GitHub, cloud
  credentials, external project tokens, or a UI runtime.
- Scheduled agents can consume `operator-status`, `handoff-summary`, `interface-decision`, and the repo-local artifacts
  directly.
- A local UI could still be useful later, but adding one now would increase operating burden before evidence shows it
  improves decision quality or agent throughput.

## Downstream Routing

- T014 should implement the selected CLI/static interface with restrained operating-tool design.
- T015 should document why CLI/static remains selected instead of adding UI-only accessibility and small-screen checks.
- T016 should document how scheduled agents use the workbench artifacts without a fragile UI dependency.

## Reopen Criteria

A future UI decision can be reopened if evidence shows the CLI/static interface no longer provides decision-ready
status, or if a local UI can improve operator review without hiding source-of-truth repo artifacts. Any reopened local
UI path must preserve CLI/static workflows for automation and testability.
