# Agent Workflow Foundation Constitution

## Core Principles

### I. Repository Artifacts Are The Source Of Truth

Objectives, specs, ADRs, research notes, BDD contracts, Beads tickets, run reports, blocked states, and learnings are durable project state.
Execution environments are replaceable. Agents must reconstruct project state from repository artifacts before planning or changing work.

### II. Human Gates Prevent Drift

Agents must stop instead of guessing when scope, priority, architecture, acceptance criteria, or product intent is unclear.
Blocked states must be recorded so a later agent can resume after a human decision is captured.

### III. Testable Behavior Comes Before Implementation

User-facing and operationally important behavior must be expressible as implementation-agnostic BDD contracts.
Tasks are complete only when the linked acceptance command and relevant workflow checks pass.

### IV. Small Slices, Traceable Tickets

Approved work must decompose into small, dependency-aware tasks linked to objective ids, spec ids, and acceptance checks.
Workers claim one ready item at a time and keep concurrent work separated through Beads and `.agent-runs/claims/`.

### V. Alpha Means No Compatibility Debt

This project has no users yet. During alpha, agents must replace incorrect structure directly instead of adding shims, compatibility adapters,
deprecated paths, duplicate APIs, or migration layers. Breaking changes are allowed when the linked spec and review gate approve them.

## Project Constraints

The repository is organized by responsibility:

- `apps/` contains runnable product implementations such as Mastra TypeScript and LangGraph Python examples.
- `packages/` contains shared contracts, fixtures, BDD contracts, and reusable assets.
- `tools/` contains project orchestration tooling, including the `awf` CLI.
- `.specify/` contains the native Spec Kit substrate generated by the Specify CLI.

The root directory must remain clean. Generated caches, egg metadata, build outputs, and oversized directories are rejected by repo hygiene.

## Development Workflow

Agents must run `uv run awf bootstrap`, inspect context with `uv run awf context-index`, and load the relevant skill before work.
Specification workflow changes must pass `uv run awf spec-kit-lint`. General workflow changes must pass spec, BDD, review-gate,
repo-hygiene, and fixture checks.

Spec Kit native work uses the installed Codex skills:

- `speckit-constitution` for governing principles.
- `speckit-specify` for feature specifications.
- `speckit-plan` for implementation plans.
- `speckit-tasks` for task generation.
- `speckit-analyze`, `speckit-clarify`, and `speckit-checklist` for quality gates.

## Governance

This constitution supersedes conflicting local process notes. Amendments require a linked objective or spec, an explanation of why the
principle changed, and successful workflow validation. Changes that alter compatibility policy, root structure, ticket semantics, or
human-gate behavior require explicit human review.
